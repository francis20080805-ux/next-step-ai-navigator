# 核心需求复核记录

复核日期：2026-10-10。范围为本地任务理解、流程规划、能力匹配、种子目录、导入和搜索；同时只读核对本机技能名称与桥接服务的接口。

## 字段与种子覆盖

- `Skill` 已包含需求附件列出的全部字段；额外保存能力种类、来源路径、内容标识及中文解释状态。`TaskIntent` 保存目标、已有／缺少内容、条件、参数和完成动作，`WorkflowStep` 保存独立步骤、顺序、依赖、能力及完成／跳过状态。
- 预置共 49 条能力：45 个真实 Skill 摘要，另有 Gmail、Google Calendar、GitHub、联网搜索 4 个服务或工具能力。
- 逐一读取本机 45 个对应 `SKILL.md` 的 YAML `name`，全部与种子名称完全一致，包括大小写不同的 `Spreadsheets` 和 `Presentations`。
- 用户明确列出的 Figma、网页开发、Remotion、Google Drive／Sheets／Docs／Slides 均已覆盖，并补充本地表格、PPT、文档、PDF、图片等常见能力。Figma、build-web-apps 等分组没有冒充独立 Skill。
- 独立技能与连接器的 `pluginId` 留空；内部稳定 ID 不变。种子 Markdown 明示是本应用整理的推荐摘要，未伪造官方完整原文，也未写入本机私密路径。

## 核心行为与 AI 接口

- “不要字幕”与“还没有字幕”分别表示排除和缺少；只有已有视频且只需字幕时直接从字幕开始。来源素材与最终输出分开判断，避免把“做好后检查”误认成已经完成。
- 标题使用短中文目标，原始需求、补充输入和参数完整保存。补充进度保留任务与步骤 ID，已完成历史不会因为转入调试而丢失；问题修好后可进入检查。
- 步骤 ID 独立于 Skill ID。整理数据、统计和图表可重复使用同一表格能力；销售 PPT 在实际数据缺失时先提示准备数据，不假设已连接云端账号。
- 本地与 AI 都使用同一个 `planWorkflow`。支持桥接 schema 的 `quantity`、`format`、`analysis`、`responsive` 等字段；补充中的空参数和 `unspecified` 不会清除已有约束。无法生成任何步骤的 AI 意图会报可理解的错误，交由服务降级本地推荐。
- 新建普通 PPT 使用 `Presentations`，现有 Google Slides 模板／编辑使用 `google-slides`。设计转网页使用 `figma-design-to-code`；仅有 Figma 字样不会要求新建设计文件。
- Markdown 导入支持 YAML 多行字段和显式分类、任务类型。未知用途保留原文并等待 AI 或人工确认，未确认能力不会进入推荐。搜索兼容中文口语、英文名和分类。

## 未变化内容与后台交接

- GitHub 扫描器的同 ID、同文件 SHA 路径保留既有解释状态，跳过再次读取和解析，符合未变化内容不重新解释的要求。
- 只读复核发现公开目录同步可能用相同内容的 `pending` 快照覆盖本机 `ready` 解释，重复导入接口也可能再次解释同一内容；已交由后端负责人修复并补充验证。本核心记录不把该后端检查项当成已完成验收。
- AI 解释返回英文分类枚举，种子展示分类为中文；已提醒界面／后端统一中文显示，避免库中出现两套分类。

## 验证与实际边界

- 核心测试覆盖视频完整参数、否定、已有素材、状态更新、同能力多步骤、销售 PPT、多目标、Figma、网页调试、可选图表、PDF 先读取、连接器区别、导入和搜索。
- 本地规则针对这些常见场景提供可运行推荐，不声称理解任意自然语言或任意陌生说明。未知场景先补充具体目标，陌生 Skill 先解释／确认；真实执行仍通过生成的 Codex 任务进行。
- Skill 的前后关联字段保存来源或 AI 的真实引用；第一版执行顺序由任务配方决定，不把 Skill 库直接当成通用自动执行引擎。
