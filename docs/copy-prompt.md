# 复制给 Codex 的执行提示词

“复制给 Codex”和“开始这个任务”弹窗中的复制按钮，都使用同一份提示词。提示词首先说明当前待办步骤的具体操作，再明确调用目录中真实的 Skill；目录有 `pluginId` 时同时指明所属插件，不推测未记录的插件名。连接器单独写成“需要连接的服务”，不会伪造 `$Gmail` 等 Skill 调用。

例如输入“我要剪一个 30 秒短视频，带字幕，最后导出 1080×1920 竖屏，不要背景音乐”，复制内容以以下指令开始：

```text
请先执行当前这一步：做视频。
使用我提供的视频素材剪辑短视频：裁掉多余片段，按原始需求调整片段顺序、节奏和画面，保留原始素材。
请调用插件「remotion」中的 Skill「remotion-create」（$remotion-create），先读取该 Skill 的说明，再按本任务的要求执行这一步。
完成当前步骤后，按下方剩余流程继续，给出实际成果文件或可核对的结果。
```

后续包含原始需求、补充记录、参数、已有材料、缺少的材料、明确排除项、已完成和已跳过的步骤。剩余流程中的每一步均带操作要求与真实能力名称，包括字幕的 `remotion-captions` 和导出的 `remotion-render`。

补充“视频已经做好了，现在还没字幕”后，旧任务的制作和素材装配步骤都保留并标记完成，复制内容从字幕操作开始，不再把制作视频列入剩余工作。若同时要求加音乐、换音乐、继续剪辑或调整素材，素材步骤仍待执行。初次输入已有视频只加音乐，也会保留音乐处理步骤。没有提供实际素材时，提示词要求 Codex 先索取文件；缺少插件或 Skill 时明确说明缺少的能力，不声称已经调用。所有步骤完成后提示保留成果，不会安排重做。

验证：`node --experimental-strip-types --test tests/core.test.ts` 中新增 8 个可运行场景，检查视频具体指令、真实插件和 Skill、本地及结构化 AI 进度前移、明确新增素材编辑、连接器、缺少材料、完成及跳过状态和目录插件元数据。浏览器剪贴板验证另见生产验证记录。
